# Dataset v0

What it contains, how it was sampled, what the audit found, and the one thing it cannot
answer.

Generated by `scripts/generate_dataset.py`, audited by `scripts/audit_dataset.py`.
Data: `outputs/dataset_v0/` (29.5 MB). Audit: `outputs/dataset_v0/audit.json`.
Decisions: `docs/DECISIONS.md` D035–D039, and D040 for the branching it rests on.

---

## 1. Shape

| | |
|---|---|
| hidden states | **512**, scrambled Sobol over `[m, µ_s, ratio, b]` |
| probe episodes | **1 536** — 3 independent repeats per hidden state |
| candidate rows | **49 152** — 32 candidate forces per probe |
| positive rate | **6.54 %** (3 213 rows) |
| invalid rate | **0.88 %** (434 rows) |
| probe history lengths | **6–56 steps**, mean 29.1, 41 distinct values |
| on disk | 29.5 MB, normalised — one recording per probe, not per row |
| generation time | 2 103 s (35 min) at 32 environments in parallel |

Task: `T = 1.5 s`, `d_goal = 40 mm`, `ε_d = 7.5 mm`, `ε_v = 0.03 m/s`, `fall_fraction = 0.35`,
8-step inference gap. Unchanged from Phase 10.

## 2. How it was sampled

**Hidden states** — a scrambled Sobol sequence over `[m, µ_static, ratio, b]` with
`µ_dynamic = ratio × µ_static`. The ratio parameterisation is not a convenience: PhysX
silently discards a `µ_d > µ_s` write (D016), so sampling a ratio keeps every draw valid by
construction rather than by rejection. Verified: `µ_d ≤ µ_s` for all 512.

Achieved ranges — mass 4.00–11.99 kg, `µ_s` 0.50–3.00 N, `µ_d` 0.17–2.84 N, `b`
2.00–9.99 N·s/m — i.e. the requested box, filled.

Sobol also gives **index stability**: drawing 512 points yields the same first 64 as drawing
64, so extending the dataset later will not renumber what it already has. `xi_id` remains a
content hash of the four values, never the index.

**Candidate forces** — 32 equal strata over 0.15–4.5 N, one deterministically jittered sample
per stratum, with the jitter derived from that hidden state's own `xi_id`. The sampler is
given an identifier and a config and **cannot read a label, an Oracle band, or a best force**
(D035). Every repeat of a hidden state is asked the same 32 forces, which is what makes
`(xi, F)` a repeated measurement (D036).

**Counterfactual labels** — one probe, then 32 candidate executions branching from a
snapshot of the post-probe state, so all 32 answer the same question. Validated separately;
see `docs/COUNTERFACTUAL_BRANCHING.md`. The branch order is shuffled per probe and every row
records its `branch_index`.

## 3. The audit: nine gates, all passed

| gate | result |
|---|---|
| identifiers unique | pass — 512 / 1 536 / 49 152 distinct |
| probe references resolve | pass — no dangling reference, no missing `.npz` |
| probes belong to one hidden state | pass |
| repeats share a candidate grid | pass — all 512 |
| finite values | pass — no NaN in rows or histories |
| no privileged field in the model's input | pass — `xi` recorded, unreachable |
| split has no leakage | pass at `xi_id`, `probe_id` and `candidate_id` |
| counts match the manifest | pass |
| branch index decorrelated from force | pass — see below |

**Force against branch position: mean correlation −0.0005 over 1 536 probes**, which is
0.11 σ against the null of a uniform shuffle. The gate is a 3-σ test (0.0137 here) rather
than a constant, because a constant is wrong at both ends — on a 16-probe smoke set the same
formula gives 0.34, correctly loose. The worst *single* probe reaches 0.63, which is expected:
with 32 candidates one shuffle's correlation has a standard deviation of about 0.18, so the
mean is the statistic and the maximum is only reported.

## 4. Splits

Grouped on `xi_id`, assigned by hashing rather than by a seeded shuffle so the partition is
stable as the dataset grows (D031).

| | train | val | test |
|---|---|---|---|
| hidden states | 359 | 65 | 88 |
| candidate rows | 34 464 | 6 240 | 8 448 |
| positive rate | 6.51 % | 6.52 % | 6.68 % |

The label balance is even to within 0.17 percentage points, so a difference between splits
cannot be attributed to the split itself.

## 5. Positive coverage — and why the candidate count is 32, not 24

This is the one design number that changed during the phase, and it changed because it was
measured.

The plan specified 24 candidates per probe. A 32-hidden-state pilot at that count gave:

| | 24 candidates | 32 candidates |
|---|---|---|
| probes with ≥ 1 positive | 85.4 % | **93.8 %** |
| probes with ≥ 2 | 54.2 % | **72.9 %** |
| hidden states with no positive at all | 2 / 32 (6.2 %) | **0 / 32** |

The two failing hidden states looked infeasible at first glance — their displacement jumped
from 6.6 mm straight to 140 mm across adjacent candidates. Reading the force-sorted rows
properly showed otherwise. One of them reached **40.1 mm at 2.61 N**, inside the position
tolerance, and failed only on terminal velocity (0.032 against `ε_v = 0.03`); its neighbour at
2.42 N gave 31.7 mm with a compliant 0.023 m/s. A force somewhere in the 0.19 N gap between
them would have succeeded. **The grid missed it; the physics did not forbid it.**

The mechanism is arithmetic: just past breakaway `dd/dF` reaches 100–130 mm/N, so a
24-stratum grid's 0.181 N spacing maps to 18–24 mm of displacement — wider than the 15 mm
success window. 32 strata give 0.136 N and 14–18 mm, which is just enough.

Raising the count globally is the remedy the plan itself prescribes for exactly this finding,
and it was applied after measuring rather than instead of.

**Dataset v0's achieved coverage:**

| | probes (1 536) | hidden states (512) |
|---|---|---|
| no positive | 90 (5.9 %) | **5 (0.98 %)** |
| ≥ 1 positive | 1 446 (94.1 %) | 507 (99.0 %) |
| ≥ 2 positives | 1 195 (77.8 %) | — |
| positive in all 3 repeats | — | 447 (87.3 %) |

Median positives per hidden state: 6 of 96 rows.

Consistent with Phase 10's Oracle, whose median required force is 1.50 N: the mass of

## 7. Invalid rows

0.88 % of rows fell outside the operating region and are kept in the file so the drop is
auditable:

| reason | rows |
|---|---|
| excessive lateral drift | 366 |
| excessive orientation drift | 225 |
| excessive velocity | 174 |
| no measurable motion | 72 |
| safety abort | 39 |
| mechanical limit | 13 |

The drift reasons dominate, and they are the known Phase 8 limitation: the held axes drift
when a compliant drawer runs a long way. They are dropped by the training script, which
reports how many.

## 8. Histories

6 to 56 steps (0.1 to 0.93 s) with 41 distinct lengths, because a probe stops when the drawer
has moved 3 mm and that takes as long as the drawer needs. The length is therefore itself
information about the drawer, which is why the recordings are stored ragged at the raw control
rate and padded per batch in the DataLoader (D037).

The seven channels are `DEFAULT_ACE_INPUT`, used directly rather than copied so the dataset
cannot drift from the observation registry. Six diagnostic channels — including `time` and the
wrist force — are stored alongside under a `diagnostic/` prefix and excluded from the model's
input, so a later ablation needs no regeneration.

## 9. What this dataset cannot answer

Recorded prominently because it bears on how the training results should be read.

`T` is fixed at 1.5 s, so the adapted parameter is one-dimensional: `p = [F_peak]`. Measured
on the Phase 10 Oracle and reproduced independently here: **the midpoint of a hidden state's
succeeding force set also succeeds for 104 of the 105 solvable states (99.0 %)**, the median
state has 3 succeeding forces on a 0.05 N grid, and only 5 of 105 have any failure inside
their own band.

So in one dimension the success set is essentially a contiguous interval whose midpoint works.
A model that predicts the whole success landscape therefore has **no structural advantage**
over one that predicts a single number — there is no multi-modality to exploit. Any gap
between ACE + PSP and a scalar regressor measured on this dataset is a gap in *regression
accuracy*, not evidence that landscape modelling is necessary.

The project owner has since decided that the adapted parameter becomes `p = [F_peak, T]`
(D034), which is what makes the question askable. Dataset v0 is the one-dimensional baseline
case; it is valid evidence about the physics, the pipeline and `F_peak` at `T = 1.5 s`, and it
is not the two-dimensional dataset that decision calls for.

## 10. Reproducing

```bash
python scripts/generate_dataset.py --headless --num-xi 512 --repeats 3 --candidates 32 \
    --num_envs 32 --dataset-version v0 --output outputs/dataset_v0
python scripts/audit_dataset.py --dataset outputs/dataset_v0
```

The manifest records the git commit, both simulator versions, the dataset seed, both samplers'
configs, the probe and execution configs, the task, the operating region, the channel lists
and the row counts. Nothing about which dataset a run used has to be inferred from a directory
name.
